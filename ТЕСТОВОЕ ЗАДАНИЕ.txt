================================================================================
ТЕСТОВОЕ ЗАДАНИЕ ДЛЯ ПРОЕКТА SUBTRACKER
=======================================

## ОБЩАЯ ИНФОРМАЦИЯ

Название проекта: SubTracker
Тип: Android приложение для управления семейными подписками
Версия: 1.0
Платформа: Android 6.0+ (API 23+)
Язык: RU/EN (если актуально)
Архитектура (ожидаемо): MVVM, Repository, Offline-first
Хранилище: Room (локально), Firebase Firestore (синхронизация), FirebaseAuth

## ЦЕЛЬ ТЕСТИРОВАНИЯ

1. Проверить, что приложение работает стабильно и соответствует требованиям.
2. Убедиться, что ключевые пользовательские сценарии проходят без ошибок.
3. Проверить корректность синхронизации данных (offline-first).
4. Убедиться, что приложение готово к релизу по критериям приемки.

## ОПИСАНИЕ ПРОЕКТА

SubTracker - мобильное приложение, позволяющее семьям совместно управлять
подписками на различные сервисы (Netflix, Spotify, YouTube Premium и др.).
Поддерживает синхронизацию данных между устройствами членов семьи, статистику
расходов, напоминания о платежах и экспорт данных.

## ОСНОВНЫЕ ФУНКЦИИ

1. Авторизация и управление семьями (создание/вход/присоединение/гость)
2. Управление подписками (создание/просмотр/редактирование/удаление)
3. Отслеживание платежей (отметить оплату, история платежей)
4. Статистика и аналитика (суммы, график, топ дорогих подписок и т.п.)
5. Настройки профиля (имя, аватар, семья/участники, экспорт)
6. Синхронизация данных (offline-first, конфликты, восстановление)
7. Темная/светлая тема

## РОЛИ И ПРАВА ДОСТУПА (ОЖИДАЕМО)

1. Администратор семьи:

* создает семью, видит код семьи
* видит все подписки семьи
* (если предусмотрено) управляет участниками/правами

2. Участник семьи:

* добавляет/редактирует свои подписки
* видит общий список семьи (если так задумано)
* доступ к статистике семьи (если так задумано)

3. Гость:

* ограниченный доступ без синхронизации
* часть функций недоступна (уточнить)

## ОБЛАСТЬ ТЕСТИРОВАНИЯ

Включено:

* UI/UX (основные экраны, навигация, состояния загрузки/ошибки)

* CRUD подписок

* Настройки профиля и экспорт
* Offline-first синхронизация

Не включено (если нет времени):

* Локализация всех строк
* Глубокие edge-case проверки на очень больших данных
* Полная проверка доступности (accessibility), если не заявлено

## ТЕСТОВОЕ ОКРУЖЕНИЕ

КРИТЕРИИ ПРИЕМКИ
================

Приложение считается готовым к релизу, если:

1. Все критичные тест-кейсы (P0) пройдены
2. Нет критических багов (блокирующих сценарии и основные экраны)
3. Нет критических утечек памяти (LeakCanary не показывает fatal issues)
4. Приложение стабильно работает на Android 6.0+ (API 23+)
5. Синхронизация данных работает корректно и предсказуемо
6. Основные экраны не имеют критичных визуальных дефектов
7. Экспорт данных работает (файл создается, корректные поля)
8. Напоминания приходят и не дублируются неконтролируемо

================================================================================
ПРИОРИТЕТЫ ТЕСТОВ (P0/P1/P2)
============================

## P0 (критично, блокирует релиз)

АВТОРИЗАЦИЯ/СЕМЬИ

* Создать семью: корректный ввод -> успешное создание -> показ кода -> вход
* Вход по имени+коду: валидные данные -> вход
* Неверный код/имя -> корректная ошибка, нет падения
* Google sign-in: вход -> привязка к семье по коду -> вход в приложение
* Гостевой вход: доступ ограничен, приложение не крашится

ПОДПИСКИ (CRUD)

* Добавление подписки: создание -> отображение в списке
* Редактирование подписки: изменения сохраняются и видны после перезапуска
* Удаление подписки: удаляется локально и (если есть сеть) удаляется в облаке
* Валидация: пустые поля/некорректные значения не проходят

ПЛАТЕЖИ

* Отметка оплаты: создается запись в истории, дата следующего платежа пересчитана
* История платежей отображается корректно

СИНХРОНИЗАЦИЯ OFFLINE-FIRST

* Добавить/изменить/удалить подписку офлайн -> данные есть локально
* Включить интернет -> корректная синхронизация в Firestore
* На втором устройстве семьи -> изменения подтянулись
* Конфликт (два устройства меняют одну подписку) -> приложение не ломается, поведение предсказуемое (последняя запись/merge по правилам)

СТАБИЛЬНОСТЬ

* Приложение не падает при переходах между экранами
* Поворот экрана (если поддерживается) не ломает состояние критично

## P1 (важно, но не блокирует релиз)

СТАТИСТИКА

* Месячные расходы считаются корректно
* Самая дорогая подписка определяется корректно
* График отображается корректно при 0/1/много подписок

НАСТРОЙКИ

* Смена имени отображается на главном экране
* Смена аватара сохраняется и не слетает после перезапуска
* Экспорт CSV: файл создается, есть основные поля (сервис, цена, период, владелец, даты)

УВЕДОМЛЕНИЯ (WorkManager)

* Уведомления приходят при приближении даты платежа
* Нет спама: не приходят дубли подряд без причины
* После отключения уведомлений (если есть) они не приходят

ТЕМА

* Переключение светлая/темная не ломает читаемость и контраст

## P2 (желательно)

* Длительная работа (10-15 минут активного использования) без лагов/утечек
* Поведение при слабой сети (потери пакетов/долгие ответы)
* Проверка на больших списках (100+ подписок, 300+ платежей)
* Accessibility базовая (крупный шрифт, TalkBack - если требуется)

================================================================================
НЕФУНКЦИОНАЛЬНОЕ ТЕСТИРОВАНИЕ
=============================

Производительность:

* старт приложения приемлемый (нет долгих зависаний)
* прокрутка списка подписок плавная (без фризов)

Надежность:

* работа без сети не приводит к потере данных
* при восстановлении сети синхронизация не ломает локальные данные

Безопасность (минимум):

* данные семьи не должны быть доступны другой семье
* при выходе из аккаунта данные/сессия корректно очищаются (если предусмотрено)

Память:

* LeakCanary: нет критических утечек при переключении экранов и повторных входах
